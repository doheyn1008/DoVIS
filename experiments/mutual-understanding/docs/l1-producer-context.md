# 생성의 시드 불안정성과 H의 별도 사전 계획

G1의 한 발견 시드는 네 언어에서 모든 목표를 넘었지만, [새690xx 시드 검증](https://github.com/doheyn1008/DoVIS/actions/runs/43647997707)은 **12개 중10개 통과, 전체 안정성 미달**입니다. 실행·출처 검증은 성공했으며 실제48개 체크포인트와 원시 평가 행, 표집 RNG, 독립적으로 다시 만든 초기 모델을 감사했습니다. 실패한 시드를 다시 돌리거나 원래 결과를 성공으로 바꾸지 않습니다.

| 언어 | 생성 replica0 /112 | replica1 /112 | replica2 /112 |
|---|---:|---:|---:|
| 한국어 | 108 | 81 | 107 |
| 일본어 | 106 | 99 | 105 |
| 영어 | 112 | 112 | 112 |
| 스페인어 | 112 | 112 | 112 |

12개 모두 이해·네 진단은 통과했고, 두 실패는 생성입니다. 일본어 replica1은 학습 장면220개를 모두 맞혔지만 새 조합에서13개 색 오류가 났습니다. 한국어 replica1의31개 오답에는 표현 인식 실패26개·미종료16개·잘못된 UTF-8 12개·도형/대상 오류5개가 있으며 항목은 겹칩니다. 두 언어의 공통 원인이 색상 하나라고 단정하지 않습니다. 원본 요약·독립 감사는 `results/l1-mastery/2026-11-14-cohort-G/`에 남깁니다.

## 바꾸는 입력과 유지하는 통제

현재 생성기는 정밀한 객체 attention과 함께 고정 CNN의 전역 벡터를 받습니다. 이 전역 벡터는 GRU 초기 상태와 **매 토큰의 반복 입력 모두**를 조건화합니다. H는 이 전역 입력의 표현이 새 조합에서의 불안정성과 관련되는지 확인하는 별도 개발 실험입니다. 기존 attention에도 색 정보가 있으므로 정보 부재나 원인을 이미 증명한 실험으로 해석하지 않습니다.

H0는 원래 CNN 벡터입니다. H1은 PNG에서 얻은 순서 없는 두 객체의34차원 token을 사용합니다. 첫32개 특징은 기존 방식으로 정규화하고 마지막 좌표는 원래 `y,x`입니다. 객체 평균34차원·Y가중평균34차원·X가중평균34차원을 이어 붙여102차원을 만들고,26개0을 채운 뒤 전체를 L2 정규화해128차원으로 만듭니다. 위치 가중항은 색이 다른 같은 도형의 좌우 배치를 구분합니다.

표현은 PNG별 고정 변환입니다. Scene·색/도형/역할 ID·언어 이름표·palette·fit/dev 통계에 맞춘 보정을 입력하지 않습니다. 실제 두 token을 쓰며24개로 복제된 attention 행의 순번에 의존하지 않습니다. 두 조건 모두 모든332개 그림의 같은 고정 캐시를 준비하고 이후 불변성을 검사합니다.

전체 NN의 구조·매개변수 수477,443개와 초기 가중치는 같습니다. G1 이해 경로, 생성기의 객체 attention, 원래 C의 자료·분할·22보호쌍 제외·시각 prior·오답 정책·학습률·분리된 gradient clipping·2,400/4,800/9,600-step 예산도 유지합니다. 학습 뒤 U가 **모든 저장 예산에서 정확히 같아야** 유효한 대조입니다. 표현·모멘트·좌표·정규화·padding을 함께 바꾸는 P 전역 조건 묶음이며 내부 요인 하나의 인과 효과를 분리하지 않습니다.

## 결과를 보기 전에 고정한 선택과 확인

발견 단계부터 새 시드 쌍 `(79007,79009)`, `(79017,79019)`, `(79027,79029)`으로 네 언어·두 조건의24개 모델을 학습합니다. 조건 하나가 후보가 되려면12개 모델 각각의 **고정 최종9,600-step 상태**에서 이해·유효 생성·네 진단의 원래90% 목표와 평가 범위를 모두 넘겨야 합니다. 후보 중12개 최종 생성 정확도의 최솟값이 높은 조건을 고르고, 정확히 동점이면 H0입니다. 후보가 없으면 선택하지 않습니다.

선택한 한 조건을 새 `(99007,99009)`, `(99017,99019)`, `(99027,99029)`로 네 언어씩12개 다시 학습합니다. 언어 가중치와 Adam/RNG는 새로 만들고 이미지 전용 C prior만 공유합니다.12개 모두 자기 최종 체크포인트에서 같은 여섯 목표와 진단 범위를 넘어야 반복된 개발 후보입니다. 발견과 확인 모두 요청당 최초 학습 진입만 허용하며 실패·중단·시간초과·누락을 보존합니다.

이 계획은 이전690xx 결과의 재시도가 아닙니다. 새 입력 표현을 새 발견 시드와 새 확인 시드에서 평가합니다. 기준 완화·중간 최고점·언어별 조건 합치기·성공한 시드만 남기기는 허용하지 않습니다. 아래에 최초 실행의 실제 결과와 집계 실패를 별도로 기록합니다.

능력 범위는 유한한5색·3도형·공간 관계입니다. 이해에는 작성된 네 문형을 사용하고 생성 훈련은 원래 첫 문형을 유지합니다. 일상 언어 능력·인간 습득·언어 거리 또는 L2 연구 적격성을 자동 부여하지 않습니다. 실제 원문 학습을 위한 더 큰 별도 구현은 [native-language](../../native-language/README.md)에 있습니다.

## 최초 H 실행의 실제 학습 결과와 집계 실패

[원본 H 실행43652561578](https://github.com/doheyn1008/DoVIS/actions/runs/43652561578)의 검증·언어 작업12개는 모두 성공했고24개 NN 학습과96개 체크포인트가 완료됐습니다. 그러나 **전체 workflow는 aggregate_h 작업132631927039의 실패로 failure**입니다. 원본 집계가 성공했다고 바꾸어 기록하지 않습니다.

원시 결과를 별도로 독립 감사했습니다. 실제96개 텐서/SHA·단계·정확한 평가 행 구성·31,872개 생성·127,488개 이해·150,528개 이진 진단·세 독립 초기화/난수/표집 흐름·보호22쌍 제외·PNG별 특징 불변성을 확인했고 오류는0개입니다. H0/H1 이해 가중치는 모든 저장 예산에서 정확히 같았습니다.

표의 각 세 숫자는 replica0,1,2이며 생성 분모112, 이해448입니다. 마지막 열은 H1의 세 replica 중 진단별 최소 정답 수로 역할/색/도형/결합 순이며 분모는448/448/432/240입니다.

|---|---|---|---|---|
| 한국어 | 112, 95, 108 | 112, 112, 112 | 446, 448, 446 | 446, 444, 432, 240 |

사전 고정한 원시 결과 규칙을 독립 적용하면 H0는 한국어 replica1 생성95/112 때문에11/12로 부적격이고, H1만12/12로 적격입니다. H1의 최저 최종 생성은111/112입니다. 이 숫자는 원래 집계 workflow의 성공을 뜻하지 않으며, **공식 복구 요약 결합 및 별도990xx 확인은 아직 수행 전**입니다.

집계 오류는 언어 간 초기 상태 서명에 고정 CNN의 런타임 특징 표 해시까지 넣은 데서 발생했습니다. 서로 다른 CPU 서버에서 발생한 두 기존 해시 그룹은 이전690xx 원시 기록에도 존재합니다. 실제 차이는 `memory_preflight.feature_tables.caches.visual_cache.sha256`와 그 표의 파생 해시뿐이었고, 초기 NN·prior·다른 특징·자료·설정은 같았습니다. 각 H0/H1 쌍 안의 전체 특징은 정확히 같고 자기 학습 전후에도 불변입니다.

이 차이를 점수 변경이나 모델 재학습으로 처리하지 않습니다. 원본 NN 소스42개와 실패·원시 파일을 유지하고, 별도 **집계 전용 복구**에서 기존690xx 기록의 정확한 두 그룹·96개 체크포인트·조건 내 통제를 검증한 후 집계용 깊은 사본의 두 메타데이터 해시만 정규화할 계획입니다. 원래 선택 함수를 그대로 적용하고 원시 평가 행은 변경하지 않습니다. 이는 결과를 본 뒤의 명시적 집계 검사 수정이며 원래 workflow 성공으로 소급하지 않습니다. 실제 복구 실행·요청·스크립트 해시와 새로운990xx 확인을 추가로 결합해야 합니다.

확인 집계에도 별도의 형식 오류를 발견해, 실제 H preflight가 기록하지 않는 `invalid_pngs`를 무조건 요구하던 부분만 수정했습니다. H의 실제332개 PNG 검사 형식과 상태/RNG/특징 불변성을 요구하며, 명시된 잘못된/양수 invalid 값과 fallback은 여전히 거부합니다. 원본9ea481a→수정7ede9cd의 AST 비교에서 `aggregate_cohort_validations` 한 함수만 달라졌고 학습·CLI 등 나머지49개 최상위 노드는 같습니다. 이는 확인 시작 전에 수정한 집계 코드이며 NN15개 구현은 그대로입니다.
