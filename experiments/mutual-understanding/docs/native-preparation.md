# 모국어 이해·생성 공동 학습 준비

첫 작은 이해 학습 다음의 **개발 실험**입니다. 한국어·일본어·영어·스페인어의 모델을 무작위 초기화부터 자기 언어만으로 학습합니다. 생성기도 이번에는 훈련합니다. 이 실행에서 만든 모델은 본실험용 모국어 모델로 인정하지 않습니다.

## 학습 전에 고정하는 조건

- 기존 연구 TRAIN 안의 물체 쌍을 학습 10쌍·개발 평가 4쌍으로 나눕니다. 학습에는 3색×3도형의 9개 물체가 모두 나오고, 개발에도 세 색·세 도형이 나오도록 의미 정보만으로 결정합니다. 모델 성적을 보고 분할을 고르지 않습니다.
- 각 쌍의 두 대상 순서×두 위치 관계 및 네 문형을 사용합니다. 학습은 40장면·160문장, 개발 평가는 16장면·64문장입니다. 개발에는 학습한 물체의 새로운 쌍이 나옵니다.
- 모국어 적격성·첫 접촉 사전검사·곡선·최종 평가의 네 보호 분할은 훈련이나 점수 계산에 사용하지 않습니다.
- 동일한 기존 `tiny-gru-v1` 구조, 초기화·학습 시드, 배치 크기, Adam 학습률을 네 언어에 적용합니다. 개발 시드는 29003/29007/29009입니다. 공개 가중치나 학습된 토크나이저는 사용하지 않습니다.
- 이해 손실과 생성 손실을 함께 학습합니다. 후보 예산은 누적 **1,200·2,400·4,800 step**이며 각각 별도 학습을 다시 시작하지 않습니다.
- 개발용 목표는 이해 정확도와 **올바르게 종료한 자유 생성 정확도 모두 90% 이상**입니다. 네 언어가 같은 후보 예산에서 모두 충족할 때만 공통 예산 후보를 제안합니다. 없으면 `null`로 남기며 기준이나 시드를 바꾸어 통과시키지 않습니다.

이 90%는 제한된 과제의 개발용 목표입니다. 성인 수준 모국어 능력, 본실험 적격성, 새로운 언어에 대한 초기 이해도의 판정 기준이 아닙니다. 모국어 학습의 CPU 실행 시간도 외국어 습득 비용으로 해석하지 않습니다. 같은 문장 수가 같은 바이트·토큰 수를 의미하지는 않습니다.

## 무엇을 측정하는가

문장으로 네 그림 중 정답을 고르는 이해 정확도와, 그림에서 문장을 스스로 만드는 자유 생성 정확도를 따로 기록합니다. Teacher forcing 토큰 정확도·생성 손실도 남기지만 자유 생성 성공을 대체하지 않습니다.

자유 생성의 엄격한 성공은 해당 의미의 네 원어 문형 중 하나와 일치하고, EOS로 종료하며, 잘못된 인코딩이나 본문 특수 토큰이 없는 경우입니다. 기존 exact match, 제한된 문법 안에서 인식한 의미 정확도·미해석 출력, 관계/대상 순서/색/도형 오류와 EOS·인코딩 오류도 보존합니다. 알아보지 못한 새 표현을 곧바로 의미 오류라고 단정하지 않습니다.

모든 점수는 작은 유한 영역의 관측값입니다. 같은 의미의 네 문형과 같은 물체 쌍의 여러 장면은 독립 표본이 아니므로 문장 수를 독립 반복 수로 세지 않습니다. 공통 예산을 골라도 독립 모델 반복으로 재검증해야 합니다.

## 실행과 결과

```bash
cd experiments/mutual-understanding
python -m mutual_lab.native_preparation --language ko
python -m mutual_lab.native_preparation --language ja
python -m mutual_lab.native_preparation --language en
python -m mutual_lab.native_preparation --language es
```

`.github/workflows/native-preparation.yml`은 전용 브랜치 `codex/native-preparation`의 관련 파일 변경으로 네 언어 CPU 작업을 시작합니다. 각 프로세스는 내부 900초·외부 17분, 전체 언어 작업은 25분으로 제한합니다. 평가는 모델 가중치·optimizer·훈련 난수 상태를 바꾸지 않는지 검사합니다.

보고서에는 분할·어휘 커버리지·설정·소스 해시, 단계별 원점수와 오답/원본 출력, 이해·생성 가중치 해시를 남깁니다. 후보 예산별로 모델·optimizer·난수 상태를 개발 전용 `.pt` 체크포인트로 저장합니다. 이 형식은 기존 native/acquisition 입력에서 역직렬화 전에 거부됩니다.

언어별 보고서와 체크포인트, 네 언어의 공통 예산 판정 요약은 GitHub Actions artifact에 90일간 보관합니다. 실패나 제한 시간 도달도 결과로 남깁니다. 실패한 언어를 빼거나 누락된 실행을 통과로 처리하지 않습니다.

## 이후 단계

이 자료에서 이해와 생성이 함께 되는지 확인한 뒤 구조·예산·평가 기준을 확정합니다. 그다음 별도의 독립 시드로 모국어 모델들을 처음부터 다시 학습하고, 보호된 모국어 적격성 평가를 적용합니다. 개발 체크포인트를 첫 접촉 모델로 재사용하지 않습니다. 외국어 상호학습 전에는 평가 문장 정책, 추정 대상·표집 방식, 초기 이해도 허용 폭도 확정해야 합니다.
